# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A VS Code color theme extension (`quasar-theme`) shipping three themes — Quasar Dark,
Quasar Ink and Quasar Navy. No runtime code: `package.json` `contributes.themes` points
VS Code at generated theme JSON. There is no `main` entry point, no activation, no tests.

The three are one structure over three palettes. They descend from the Quasar design
system's `ui_kits/vscode-theme` (Claude Design project `ccbbb186-aa76-4711-b028-9eb070774676`),
which is the upstream source of truth for the colour values.

## Single source of truth

**[src/quasar.yaml](src/quasar.yaml) is the only place colors are edited.** Everything in
`themes/` is generated by `scripts/build.js` and is **gitignored** — edits there are silently
destroyed on the next build.

The file is one shared structure plus three palettes (`dark`, `ink`, `navy`):

- A value written `$ROLE` resolves from the `palettes` block at the top.
- A literal `'#rrggbb'` is used as-is. Hex **must** be quoted; bare `#` starts a YAML comment.
- `~` omits that key (`generate.js` drops nulls). Note it drops *only* null — `fontStyle: ''`
  is meaningful and must survive, since it clears inherited italic/bold. Nothing uses `~` at
  present: the palette defines all 638 keys.
- `!alpha [$ACCENT, '1f']` appends a constant alpha suffix.

There are 54 roles over 641 color keys, and **every** color value in `colors`,
`tokenColors` and `semanticTokenColors` is a `$ROLE` — there are no literal hexes left
below the `variants:` line. Hex appears in exactly one place: the palettes themselves.
Adding a color means defining a role and referencing it, never inlining a hex.

That discipline is what makes three palettes possible at all: every binding moves when a
role moves, so a variant is a palette and nothing else.

Roles split into three groups. Neutrals and accents that are **fixed** across all three
variants (`ACCENT`, `FG_BRIGHT`, the ANSI 16, the slider ramp); the **per-variant surface
ramp** (`SURFACE_CHROME` < `SURFACE_PANEL` < `SURFACE_RAISED` < `SURFACE_HOVER`, plus
`SURFACE_EDITOR`, `SURFACE_TAB_ACTIVE`, `BORDER`, `MUTED`, `FAINT`); and the
**per-variant syntax ramp** (`SYN_STRING`, `SYN_FUNCTION`, `SYN_TYPE`, `SYN_VARIABLE`,
`SYN_OPERATOR`, `SYN_COMMENT`, `ACCENT_ACTIVE`).

Watch for roles that share a value in one variant but not another — `SURFACE_CHROME` and
`SURFACE_SUNKEN` are both `#0e0e14` in Dark but diverge in Ink, and `FG_ON_ACCENT` and
`SURFACE_APP` are both `#14141c` everywhere. They are deliberately separate roles; do not
collapse them.

```bash
npm run build     # src/quasar.yaml -> themes/quasar-{dark,ink,navy}-color-theme.json
npm run verify    # deep-compare generated output against what's in themes/
npm run lint      # scrape the VS Code theme-color reference; report unsupported/missing keys
```

`npm run verify` is the safety net. Because `themes/` is gitignored, a generator bug that
silently drops keys would otherwise be invisible. Run it after touching `scripts/`.

## Build pipeline

- [scripts/generate.js](scripts/generate.js) parses the YAML and returns `[{file, theme}]`,
  one per entry in `variants` (`dark`, `ink`, `navy`). It **throws on an unknown `$ROLE`**
  rather than emitting the literal string, and strips the `palettes`/`variants` scaffolding
  from its output.
- [scripts/build.js](scripts/build.js) writes each to `themes/<file>`.
- `vscode:prepublish` runs the build, so `vsce package` and `vsce publish` regenerate first.
  This is what makes gitignoring `themes/` safe.

The pipeline descends from the Dracula theme's scripts, but `transformSoft` is gone.
Adding a fourth variant means adding a palette under `palettes`, an entry under
`variants`, and a matching entry in `package.json` `contributes.themes` — nothing else.

## Running / debugging

Press `F5` (launch config `Extension` in [.vscode/launch.json](.vscode/launch.json)) to open an
Extension Development Host. Select **Quasar** via `Preferences: Color Theme`. Theme JSON edits
apply live in that window — but remember they'll be overwritten, so make the change in the YAML
and re-run `npm run build`.

To find which TextMate scope a token has, run `Developer: Inspect Editor Tokens and Scopes` in
the dev host before touching `tokenColors`.

## Packaging

`npm run package` produces a ~21 KB VSIX with zero warnings. `npm run publish` needs a Personal
Access Token for the `sailfact` publisher.

`.vscodeignore` excludes `src/`, `scripts/`, `CLAUDE.md`, and all of `assets/` except
`assets/icon.png` (the 128x128 marketplace tile). Keep the `assets/**` + `!assets/icon.png` pair:
without it, any art added back to `assets/` ships in the VSIX. Verify with `npx vsce ls`, which
should list 8 files (5 metadata + 3 themes).

## Known quirks

- `contrastBorder`/`contrastActiveBorder` must stay unset. VS Code registers them as `null` for
  both light and dark and gives them values only in the high-contrast themes; a `vs-dark` theme
  that sets them gets HC chrome, i.e. an extra box drawn around focused and active elements
  (panel tabs were the visible symptom). Several other HC-only keys are still set deliberately —
  `editor.findMatchBorder` and the transparent `*.Border` no-ops — but those are local, not global.
- `gauge.*` and `inlineChat.regionHighlight` were dropped: VS Code deregistered both, and the
  color-theme schema now rejects them. `testing.message.error.decorationForeground` was likewise
  removed upstream, replaced by `testing.message.error.badge{Background,Foreground,Border}` —
  which is what the YAML sets now. The `OPT_*` roles existed only for those keys and are gone
  with them; `npm run lint` is what catches the next such removal.
- The upstream design-system themes still ship all five of those keys, plus
  `contrastBorder`/`contrastActiveBorder`. **Do not copy them back in when re-syncing from
  the design project** — `npm run lint` must stay at zero "Unsupported key" warnings.
  Conversely, the design themes omit `editor.wordHighlight{,Strong,Text}Border`; Quasar sets
  them transparent on purpose, to suppress the default box VS Code otherwise draws.
